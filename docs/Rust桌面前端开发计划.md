# FrameLab Rust 桌面前端计划

完整版和 NVIDIA 单文件版共用 `desktop/` 源码，打包时使用 `portable` 特性。两版的全新配置均默认选 VFG High。构建和本机使用入口见 [README](../README.md)。

## 布局

- 左上显示所选素材的原视频，保持宽高比。下方提供播放、暂停、首帧、逐帧和可拖动的进度条。首版只播放画面。
- 右下为可滚动的素材列表，支持一次多选导入、拖放、选择与移除。每项拥有独立的设置和导出状态。待导出时显示源帧率，导出时卡片底色从左向右填充，卡片保留文件名和总进度百分比，底部显示当前阶段与计时。完成后在卡片上显示总用时。
- 右侧底部固定导出位置和批量导出按钮。导出可逐项暂停、恢复，完成后可打开导出目录。
- 右上编辑所选素材的超分、插帧与技术路径。技术路径控制串联顺序和输出容器。只保留系统窗口标题栏，应用内没有顶栏。

## 实现

1. 使用 Rust、eframe/egui 和 Windows 原生文件对话框。FFmpeg 在后台解码小尺寸 RGB 预览，ffprobe 提供尺寸、帧率与时长。预览保留源视频，模型推理交给现有 Python 内核。
2. 单文件版的超分和插帧分别提供 VSR Ultra、VFG High，均可关闭。完整版另有 BasicVSR++、SeedVR2 3B／7B、Lanczos、GIMM-VFI、RIFE 4.25 和原帧延展。素材继承导入时的默认配置，此后按素材保存尺寸、目标帧率、顺序、容器、适用模型的光流尺度和输出目录。
3. 完整版通过 `run_video_lab.ps1` 调用 `run`、`pause`、`resume`，解析逐行 JSON 事件。批量导出按顺序执行，每次只启动一项。为每项保留独立 `.job`，既有成片与作业目录不覆盖。持久化列表、参数、目录和作业地址，重开后可续跑中断项。
4. 验收包括多选导入中文路径、切换素材时独立配置、预览定位、真实内核导出、进度和作业恢复。

## 首版接入边界

内核已通过本机短样、白鹤整段和作业恢复验证。真实长片 GPU 上限和跨段画质仍待评估。分辨率预设为 1080P、2K（1440P）和 4K（2160P），也可输入尺寸。帧率预设为 24、30、60 和 120 fps，支持 1–240 fps 的自定义值。输入沿用内核的逐行 BT.709 SDR 和恒定帧率限制。

CLI 中的切点标记、自动切点阈值、截取帧范围、分块与精度调节、环境自检和评分先保留在命令行。导入视频后可从播放器左上角进入「复核模式」，退出按钮出现在原位。标记选择、坏帧和镜头类型在同一行。黄色标记在生成预览后变绿。方向键逐帧，空格播放或暂停，长按前后帧按钮或方向键以每秒 10 帧步进。修复前后共用播放位置，退出复核返回素材预览。短循环和预览音轨、字幕仍待接入。 [复核用法与验收](VFG-错帧排查与测试备选.md#人工复核与局部补跑) 待日常菜单收敛时，保留评估入口，并验证已有素材配置和旧作业的续跑。FFV1 MKV 与 H.264 MP4 沿用现有内核导出规则。

## 本机验收

- Windows 正式版窗口已检查。两段中文路径素材用各自的配置在同一队列完成导出。640×360 的验收甲以 GIMM-VFI 导出 H.264 MP4，12 帧变为 24 帧。验收乙以原帧延展导出 FFV1 MKV，16 帧变为 32 帧。
- Rust 导出适配层通过真实 GIMM-VFI 作业验证暂停与恢复，恢复后生成成片。窗口上的暂停按钮仍待单独手测。
- 初次用 160×90 素材和 0.5× 光流尺度触发 GIMM-VFI 的尺寸错误，随后的队列项仍正常导出。

## 目标帧率与阶段切换验收

- Windows 窗口以合成素材验收了 2K、30 fps、绿色进度与总用时。短样校验了四个帧率预设和自定义小数帧率，GIMM-VFI 的 120 fps 短样验证了三轮插帧。
- 韩信旧作业最后一块到无损中间文件校验完成耗时 3 分 24 秒，生成约 3.75 GB 的 `assembled.mkv`。7B 阶段启动到首个分块提交耗时 4 分 51 秒，其中包括扫描中间片、模型初始化和首块处理。
- 新路径用同片源短样跑通 GIMM-VFI → SeedVR2 7B、4K/48，分块落盘到下一阶段启动约 1 秒。前后两种衔接方式在跨块的 21 帧上像素哈希一致。
- 韩信全片复用并校验了原作业的 97 个 GIMM-VFI 分块，再串联 Lanczos 输出 2560×1440、30 fps、604 帧。944 个 AAC 包的内容哈希和时间戳一致。该次验收未覆盖完整 7B 导出。

## 60 秒缓存与批量恢复验收

- 使用桌面批量和暂停去调用真实 Python 内核。60 秒 540p24 循环样片经 RIFE → VSR 输出 720p60、3600 帧。暂停后复用已编码分段，恢复后自动完成 GIMM-VFI 和 BasicVSR++ 两项。
- 三项均核对 CFR、分辨率、帧数和 AAC 内容与时间戳。该验收从 Rust 测试调用窗口使用的队列、暂停和进度处理入口。耗时和缓存见 [快速导出开发计划](VSR与VFG-快速导出开发计划.md)。

## NVIDIA 双版本回归

Rust 测试 `exports_nvidia_modes` 走桌面导出适配层，依次验收纯 VFG、纯 VSR 和 VFG → VSR。设置 `FRAMELAB_QA_INPUT` 为带音轨的 CFR 短片，`FRAMELAB_QA_OUTPUT` 为本轮独立输出目录。完整版的 `FRAMELAB_QA_ROOT` 指向仓库，单文件版指向解包后的运行时。运行 `cargo test --release --locked --manifest-path desktop/Cargo.toml exports_nvidia_modes -- --ignored --nocapture`。单文件版在 `--` 之前加入 `--features portable`，打包产物可用 `--verify-runtime` 触发并验证解包。

2026-11-26 用同一段 1080p24、16 帧的韩信短片验收。两版纯 VFG 均输出 1080p48、32 帧，纯 VSR 均输出 1440p24、16 帧，串联均输出 1440p48、32 帧。三组的 33 个 AAC 包与输入逐包一致，两版本的 320×180 灰度缩略图逐帧一致。单 EXE 已验证首次解包及再次启动复用。
