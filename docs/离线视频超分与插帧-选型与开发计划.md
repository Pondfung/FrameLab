# 离线视频超分与插帧选型与开发计划

2026-11-26 · Windows 11 · RTX 5070 12 GB

## 1. 产品范围

日常导出采用 VFG High 插帧和 VSR Ultra 超分，支持单项和先插帧后超分的串联。原片细节和运动连续性优先。其他模型在既有试片上的可见收益有限，整片耗时较高，保留权重与评估入口。特殊素材可用现有 Topaz 处理。输入范围及两个版本的实际用法见 [README](../README.md)。

## 3. 保留模型与评估条件

- **局部插帧**保留 RIFE 4.25 和 GIMM-VFI-R-P。FrameLab 现有两个适配器每轮都只取中点。评估顺序、三倍插帧时刻和 FixDeadFrame 规则的接入条件见 [VFG 错帧优化计划](VFG-错帧排查与测试备选.md)。 [vs-rife](https://github.com/HolyWu/vs-rife/blob/master/vsrife/__init__.py) · [GIMM-VFI 作者实现](https://github.com/GSeanCDAT/GIMM-VFI) · [Kijai 封装](https://github.com/kijai/ComfyUI-GIMM-VFI)
- **超分专项**用两段原生 4K 素材派生低分辨率输入，固定帧率、尺寸、色彩处理和切点，以 VSR Ultra 为日常参照，比较 Lanczos、BasicVSR++、SeedVR2 3B INT8 和 7B FP16。先看文字、脸、发丝和跨帧闪烁，再看指标、耗时和峰值显存。另取真实压缩素材复看，Topaz 可作外部参考。
- BasicVSR++ 可对照 REDS4 和 Vimeo90K bicubic 权重，常用权重固定重建 4× 再缩到目标尺寸。SeedVR2 的 3B INT8 走 ComfyUI，7B FP16 走 NumZ。虞姬 720p 五帧曾测得 7B 为 29.90 dB／0.920、3B 为 26.87 dB／0.874（PSNR／SSIM），人工复看因 7B 增添错误细节而选了 3B。按镜头保留这个判断。 [BasicVSR++](https://github.com/ckkelvinchan/BasicVSR_PlusPlus) · [权重与分块](https://github.com/HolyWu/vs-basicvsrpp/blob/master/vsbasicvsrpp/__init__.py) · [SeedVR2](https://arxiv.org/abs/2506.05301) · [NumZ 后端](https://github.com/numz/ComfyUI-SeedVR2_VideoUpscaler)

## 4. 用 H:\video test 做选型

下表列出最初用 ffprobe 逐帧检查的五段 24 fps 素材。它们均为 H.264、逐行、yuv420p、帧 PTS 等间隔的 24 fps，均有 AAC 双声道。从原片每两帧留一帧，做 12→24 回测，以被抽掉的帧作真值，再以正常速度盲看实际 24→48 成片。

| 文件 | 原尺寸与视频时长 | 优先看的位置及现象 |
| --- | --- | --- |
| 湖面如镜，白鹤伴飞2-许负1级.mp4 | 1920×1080，10.042 s，241 帧 | 2.5～5.5 s 测飞翅与暗部。5～8 s 补看船体、反光。色彩标记缺失。音频比视频长约 58 ms |
| 班超_20260817_113713_fengyutang.mp4 | 1920×1080，15.042 s，361 帧 | 5～9.5 s 测俯冲和城墙边缘。10.208 s 的切点已人工核对。色彩标记缺失。音频比视频长约 30 ms |
| 虞姬1级_partA_0813.mp4 | 3840×2160，9.000 s，216 帧 | 0.792 s 从黑场切入人脸，1.25～3.25 s 看睫毛、发饰与肤色，5.5～8 s 看细线条与衣袖。有 18 处相邻帧像素完全相同 |
| 陈汤_2级_partA_0811-1.mp4 | 3840×2160，17.083 s，410 帧 | 约 4.4～7.2 s 测沙尘、遮挡和高速运动。约 2.167～4.167 s 用于超分有参考测试 |
| 韩信_2级_PART_A_0720.mp4 | 1920×1080，20.125 s，483 帧 | 约 5.2～8.3 s 清点镜头切换并看飘动旗面的「漢」字和阵列细节。18.667 s 切到黑场已人工核对，文件尾部有 33 处相邻帧像素完全相同 |

两段 1080p 源缺少 primaries、transfer、matrix 和 range 标签，当前按 BT.709 limited 处理，应在画质对照时检查暗部和灰阶。输入覆盖参数仍待开发。其余三段明确标记 BT.709 limited。保留原音轨 PTS 和现有尾差，整轨复制时用流时长检查。首尾不同长是这批真实测试的一部分。原片已有的重复帧需在插帧复检中标记为原帧，以免误修。

### 已准备的基线

以下三段已用本机 FFmpeg 派生为 FFV1 文件，已读回核对尺寸、帧率和帧数。帧号从 0 开始，起始帧计入。PSNR/SSIM 是全帧各平面汇总，另需按局部纹理做盲看。

| 对照短片 | 派生与评分方式 | 无模型基线 |
| --- | --- | --- |
| 虞姬，起始帧 30，48 帧 | 4K 以 Lanczos 降到 960×540，恢复到 3840×2160 与源帧比较 | Lanczos 44.35 dB / SSIM 0.9910 |
| 陈汤，起始帧 52，48 帧 | 同上 | Lanczos 54.61 dB / SSIM 0.9975 |
| 白鹤，起始帧 60，72 帧 | 每两帧留前一帧，派生 1080p12，重建 24 fps。只给前后有锚点的 35 个缺失帧计分 | 原帧延展 27.85 dB / SSIM 0.9349 |

《陈汤》这一段 Lanczos 基线已很高，评估模型时同时查看局部沙地、毛发、装备和面部，并补更富纹理的镜头。两段 4K 源可追加一份可控压缩的 540p 派生片，区分干净降采样与压缩修复。基线用于后续 A/B。模型已跑通，跨素材的画质排名仍待评估。

## 5. 已实现的作业能力

Rust 桌面与 Python CLI 已支持逐项配置、批量导出和分块续跑。VFG 直接按目标 CFR 时间点生成。快速串联在显存中将帧交给 VSR，末级回读内存，经 FFmpeg 写成独立的 H.264 NVENC 分段。暂停和校验以已提交分段为界，完整作业封装兼容的原音轨与字幕。其他组合的内存交接及 FFV1 适用范围见 [快速导出实测](VSR与VFG-快速导出开发计划.md)。

## 6. 后续顺序

1. 完整版与单文件版已共用构建和回归入口，已完成固定切点的 SDK 开关对照、独立自动切点试验和 CLI 生成帧复检。已接入主播放器单帧标记、范围推断和修复前后对照。完整版提供 VFG 倒序、RIFE 和 GIMM-VFI 局部候选。下一步验收短循环对照，并在独立高速镜头中记录人工选择结果。实施步骤、1126 样本及通过条件统一维护在 [VFG 错帧优化计划](VFG-错帧排查与测试备选.md)。
2. 对仍失败的区间评估局部补帧。超分按第 3、4 节开展专项比较，两类模型都按多段素材的可见收益决定是否启用。
3. 已有 60 秒循环样片 GPU 批量恢复和 10 分钟低分辨率合成片时间线验收。10 分钟以上真实素材及原尺寸 4K 长片的 GPU 开销、分段接缝与音画尾差仍待验收。VFR、10-bit 和 HDR 保留作后续输入扩展评估。界面现状和待接入项见 [Rust 桌面前端计划](Rust桌面前端开发计划.md)。
